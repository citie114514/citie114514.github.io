一块 Kingston DataTraveler 3.0，128GB，用了两年多。某天插在机器上正读写着，断电了。再插回去，磁盘管理里显示"无媒体"，容量 0，盘符消失。

这种症状一般是主控进了保护态或者 MP 参数区出了问题。手上有个 `Formatter_SiliconPower.exe`（群联 PreFormat 的换皮版），跑了一遍，盘回来了：123,749,337,600 字节，exFAT，读写正常。

但是名字变了。

```
设备描述: USB 大容量存储设备(silicon-power USB Device)
USB设备ID: VID = 13FE PID = 0100
设备供应商: (空)
设备名称: silicon-power
产品修订版: PMAP
主控型号: PS2251-19(PS2319) - F/W 10.04.5D [2021-09-29]
闪存识别码: 983E980376E4 - KIOXIA(铠侠) [TLC]
```

`13FE` 是群联自己的 VID，`0100` 是它的默认 PID。那个 SP 工具不只是格式化了盘，还把整个描述符区写成了群联出厂默认值，顺手换了个序列号。

从注册表的历史记录里翻到了它原来的样子：

```
VID_0951&PID_1666  ->  Ven_Kingston  Prod_DataTraveler_3.0  Rev_PMAP
序列号 408D5C15CB50E731B909061F
```

`0951:1666` 才是 Kingston 的 ID。想改回去，得写主控的 MP 参数区，这不是改注册表能解决的。

## 第一次尝试：用错了年份的工具

查到群联有个叫 Info updater 的轻量工具，专门改 VID/PID/厂商/产品名，不用量产，不丢数据。听起来正好。

问题在于版本。这个工具最后一版是 2016 年的，而盘里的固件是 2021-09-29 的，差了五年。厂商命令的协议早就不一样了。

填好 `0951` / `1666` / `Kingston` / `DataTraveler 3.0`，点"取得信息"，界面上的设备槽显示：

```
驱动: E  0 MB
60 14
```

容量读成 0，还带个错误码。这是明显的通信失败信号，但我还是点了"开始"。写命令发过去，主控直接不干了，盘变成"无媒体"。

拔下来等了十几秒，插回去，自己好了。容量、文件系统、描述符全都回到点之前的状态。主控只是进了保护态，参数区一个字节都没被写坏。

这条经验后面很有用：**PS2251-19 被打进无媒体状态时，先试断电重插，很多时候它自己会回来。**

## 第二次尝试：换同代工具

2016 年的工具不行，那就找 2021 年的。`STTool V3.81.12 SZ 2021.06.18`，比固件早三个月，明确写着支持 PS2251-19 / PS2319。

下载包 5.8MB，MD5 `5F93E734F975D869ADE2F470A595095F`。解压后 112 个文件，结构是标准的：

```
STTOOL_F1_90_v200_00_SZ.exe          主程序
MPParamEdit_F1_90.exe                参数编辑器
ST.ini                               配置
MPAll.dll                            量产核心
BIN_FW/b2319_bank.bin                PS2319 主控固件
ISP_INFO/2319_TLC_TSB_20210615.BIN   铠侠 TLC 颗粒固件
FlashInfo.csv                        闪存型号库
```

固件是对得上的。`ST_ISP.ini` 里 TSB 3D TLC 那几行明确映射到 `2319_TLC_TSB_20210615.BIN`，而我的闪存 ID `983E980376E4` 在 `FlashInfo.csv` 里能匹配到 `***KIOXIA-BiCS5`（CSV 里第 6 字节是 `0x64`，工具读到 `0xE4`，差 `0x80` 是 Toggle 标志位，掩码后同一个颗粒）。

### 踩到的坑

**1. `IC Type` 的写法**

我按 `PS2251-70` 的格式类推，写了 `IC Type=PS2251-19`。结果主控那栏一直是空的。

翻 `MPAll.dll` 里的字符串才发现，工具内部认的标识是 `2251-19U2`、`2251-19U3`、`HG2251-19`，根本没有 `PS2251-19` 这个东西。UI 里下拉框的实际值是 **`2251-19U3`**（USB3 版）。

**2. 序列号被截断**

参数编辑器里勾上 `Enable USB SN`，选 `Fixed SN Format`，填了完整的 24 位 `408D5C15CB50E731B909061F`。界面上括号显示 `(24)`，看着没问题。

保存后读 ST.ini：

```ini
SNType=3
SNDigit=12
CustomerSerialNumber=408D5C15CB50
```

只剩前 12 位。旁边那个 `Digit` 下拉框还是 12，保存时按它截断了。改成 24 再保存，才写进去完整的。

**3. 编辑器会重置描述符**

这个问题最坑。在 `IC_FW` 页把主控设成 `2251-19U3` 并保存后，回来看 ST.ini：

```ini
[PenDriveMP]
IC Type=2251-19U3          <- 这个对了

[Customize Info]
USB VID=0x13FE             <- 被打回默认
USB PID=0x3E00             <- 被打回默认
String Product Name=USB DISK 3.0   <- 被打回默认
                           <- String Manufacturer Name 整行被删了
```

原因是编辑器在写主控型号时，按"USB 3.0 + 2251-19U3"这套组合重新加载了默认模板，把之前填的描述符覆盖掉了。序列号倒是保住了。

所以顺序只能是：所有 GUI 操作做完，最后用文本直接把描述符写回 ST.ini，之后不再打开编辑器保存。

**4. "设定"按钮的"未响应"**

点主界面的"设定"，主窗口标题立刻变成 `(Not Responding)`，任务管理器里 `Responding=False`，看起来像卡死了。

其实不是。这个按钮是调起 `MPParamEdit` 并模态等待它关闭，主线程在等，所以显示未响应。在编辑器里点保存或取消，主窗口马上活过来。

我一开始把它当成 bug，白折腾了很久。

### 最终配置

```ini
[PenDriveMP]
IC Type=2251-19U3

[Customize Info]
USB VID=0x0951
USB PID=0x1666
String Product Name=DataTraveler 3.0
String Manufacturer Name=Kingston
Inquiry Version=PMAP
FWType=0
SNType=3
SNDigit=24
CustomerSerialNumber=408D5C15CB50E731B909061F

[Firmware]
ISP=0                 <- 不烧固件，只写参数区

[Sorting]
DoSorting=0
DoMPALL=1
```

12 项全部核对通过。工具窗口标题会显示 ST.ini 里的 `Title` 值，我拿它当"配置是否被读取"的探针，改一下立刻能在标题上看到，这个方法挺好用。

## 按下开始之后

设备识别出来了，槽位显示 `1(E:)`，红框里是 `ID_03 [98 3E 98 03 76 E4 8]`，闪存 ID 正确。`开始` 按钮可用。

点下去，界面有反应：`开始` 和 `停止` 都变灰，右上角计时停在 `T:0's`，红框颜色也褪了。

但盘没有任何变化。型号还是 `silicon-power`，VID 还是 `13FE:0100`，序列号还是 `19AA9472E96E`。查进程的 I/O 计数，从启动到那一刻累计只写了 21,817 字节，就是保存 ST.ini 的大小，从来没往闪存写过东西。

勾上 `自动量产` 再点 `更新`，`更新` 反而变成禁用，还是什么都没发生。没有任何错误弹窗，也没有日志文件。

## 这个包是干什么的

`STTOOL_V381_12_SZ_20210618_MOD` 这个名字在 flashboot 上的原始描述是 **"for HG2309/HG2319 HLF UDP"**，主要是给宏芯宇 HG2319（群联授权版）做分选和测试的。

`MPAll.dll` 里有 `C2319Controller`、`C2319NController` 这些类，说明它确实认识这个主控。但它缺完整的量产路径，所以 `开始` 按钮只是把界面状态改了一下，实际的 MP 流程没起来。

数码之家上对这个主控的原话是"2251-19 别折腾"。我一开始以为这是别人没找到方法，现在看，更可能是一批人试过了。

## 一次误判

中途我看到盘的分区表从 MBR 变成了 GPT，还多了一个 32MB 的小分区，一度以为量产其实执行了、只是描述符要重新枚举才生效。

后来发现那是 Ventoy 留下的：Ventoy 默认用 GPT，第二个分区就是 32MB 的 VTOYEFI。跟量产一点关系都没有。

`Get-Volume` 一查就露馅了：

```
E:        Ventoy     exFAT   115.22 GB
(无盘符)   VTOYEFI    FAT      31.70 MB
```

这件事提醒我，判断"操作是否生效"不能只看一个间接指标，得找到能直接证伪的证据。后面我改用进程 I/O 计数和文件字节数，才不会再被绕进去。

## 结果

型号没改回来。序列号也没能写回原厂值，虽然 ST.ini 里配置是对的，但量产没执行，等于没写。

盘本身没事：

| 项目 | 结果 |
|---|---|
| 容量 | 123,749,337,600 字节，115.25 GiB |
| 读速 | 77–91 MB/s |
| 写速 | 34–51 MB/s |
| 状态 | exFAT / GPT / Healthy |

从断电卡死到这一晚上结束，它经历了 SP 工具 PreFormat、Info updater 打挂、两次 STTool 尝试、h2testw 写了 30GB，一次都没真坏。

## 后半场：把数据搬回 U 盘

既然盘还是好的，那就当普通盘用，把数据放回去。

数据源是 NAS 上的 OpenList（端口 5244，WebDAV 接口），里面有个 `内部存储` 目录，按类别分好了：`01_实用工具`、`03_手机刷机`、`04_网络代理`、`05_字体字库` 一直到 `12_上传下载`，还有 `配置备份`。总共 7,377 个文件、27.94 GB，大部分是可再下载的软件安装包。

顺带也把 `内部存储` 往 `移动云盘/磁贴` 补了一遍。WebDAV 的 `COPY` 方法在这里特别好用，服务端直接复制，不经过本地：1.91 GB 的 USBOS 用了 15 秒，约 130 MB/s。25 个小项也是秒过。

只有一个 7.2 GB 的 `字库备份_黑鲨3.7z` 上不去。试了三条路：

| 方式 | 结果 |
|---|---|
| 服务端 COPY | HTTP 500，45 秒，0 字节 |
| 管道直传 | 405 Method Not Allowed |
| 落盘后带 Content-Length 上传 | 7.2G 传到 60 秒断；3GB 探针 560 秒超时；200MB 成功 |

200MB 能传、3GB 不行，说明是云盘侧的单文件体积限制，WebDAV 层改不了。放弃。

U 盘那边顺利得多。先做差集：源 7,377 个文件，U 盘已有 6,926 个，缺 450 项 4.12 GB。

```
(根目录)        2 项   1.93G
03_手机刷机    439 项    602M
06_桌面美化      1 项     45K
07_游戏          8 项   1.60G
```

450 项全部传完，0 失败。因为文件大小从几百字节到 1.9GB 都有，速度波动很大，小文件单个 0.1 秒，USBOS 那种走满带宽。

传完做全量审计：源和 U 盘同名文件 7,376 个，**大小不一致 0 项**。U 盘上多出 230 个文件，是我自己放的 Ventoy 主题和配置，没动。

只有一个例外：

```
07_游戏/PC游戏/Metro 2033 Redux V 0.1.0.0 PLus 7 Trainer 64.EXE
源:   13,476,352 字节  sha256 ea1a2016...
本地: 13,476,352 字节  sha256 fca0bab7...
```

字节数完全一样，哈希不同。这是之前就放在 U 盘里的同名文件，和 NAS 上是不同构建。按"只看名字不算 MD5"的规则，没有覆盖。

## 留下的东西

整个过程写了一些脚本，都在 `C:\Users\citie\`：

| 文件 | 用途 |
|---|---|
| `dav_usb_sync.py` | 内部存储 → U 盘 增量同步，支持 `--dry-run` 和 `--allow` 单文件批准 |
| `dav_audit.py` | 源与目标全量大小对账 |
| `dav_diff.py` | 两个 WebDAV 目录的名称差集 |
| `dav_verify.py` | 抽样哈希校验 |
| `verify.ps1` | U 盘身份验收（VID/PID/型号/容量/读速） |
| `usb_pending_approval.txt` | 超大文件待批准清单 |

`dt3-restore/` 里留着 STTool 的完整配置和踩坑记录，万一以后有新的工具版本，照着做就行，不用从头试。

## 最后

盘现在是一块 128GB 的普通 U 盘，Ventoy 双分区完好，40GB 数据在里面，插上就能用。名字显示 `silicon-power USB Device` 而不是 `Kingston DataTraveler 3.0`，仅此而已。

保修是回不来了。金士顿的条款里写着"原始识别信息已经被修改"不予保固，现在 VID/PID 和序列号都对不上外壳标签。不过这块盘从一开始就不是拿去保修的，它断电那次能活下来已经算运气好。

那句"2251-19 别折腾"，我用一晚上验证了一遍。结论是：对。
